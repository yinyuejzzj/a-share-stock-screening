# 系统检查与修复记录

日期：2026-11-16。

检查从首次公开版本开始。先核对源码与远端提交，再运行既有24项测试；原测试全部通过，但新增输入边界和模块接口复现揭示了未覆盖的问题。以下修复都对应可重复的输入或接口测试，未通过收益表现反推参数。

## 已确认的根因与修复

| 模块 | 复现证据 / 根因 | 最小修复 |
|---|---|---|
| 尾盘分时 | 取数器输出 `time_str`，过滤器读取 `time`，有效分时也被当作解析异常 | 统一数据边界列名，并覆盖旧缓存与真实取数器输出到过滤/评分的回归 |
| 尾盘股票路由 | `000001` 个股误用了上证指数的交易所例外 | 个股路由与显式指数路由分开 |
| 沪深300取数 | 首选接口实际返回英文 `close`，读取端只识别中文列，正常响应被迫走备用源 | 兼容实际英文/中文收盘列，并测试首选源不会无故降级 |
| 尾盘缓存评分 | JSON 把涨幅窗口整数键转成字符串；同一股票缓存前后得分不同 | 评分前归一化窗口键，保持冷/热缓存结果一致 |
| 尾盘板块 | 历史请求起止同一天；需要6个收盘价却只检查5个；板块映射没有传给评分行 | 扩展真实历史窗口、分开校验3/5日样本数、将股票所属板块写入评分输入 |
| 尾盘股票池 | 全市场名单获取失败后，硬编码的少量股票可能被当成全市场 | 移除伪全市场名单，失败交由真实备用源或明确失败 |
| 尾盘报告 | 生效阈值没有呈现；改退出参数后文字仍写旧百分比和旧时间 | 报告显示实际阈值，退出说明由当前配置生成；竞价不再给出虚构的可预测区间 |
| 尾盘包导出 | `__all__` 声明了不存在的模块，通配导入报错 | 对齐实际模块名 |
| EMA 量纲 | 100手历史量与10000股实时报价表示相同成交量，却生成约4.81倍量比 | 新浪备用日线及实时量从股转手；默认仅日线，实时显式开启 |
| EMA 日期 | 旧报价日期早于历史末日仍被追加，旧值成为末行 | 实时必须为今天；拒绝旧/未来报价，同日替换并排序 |
| EMA 数据与输出 | 负成交量可触发缩量信号；非有限价格、重复日期和矛盾高低价未拒绝；新输出目录报错 | 数据边界验证；最新零量拒绝信号；创建输出父目录并明确报告写入失败 |
| 跳空数据 | 开盘20、最高9、收盘8这类矛盾K线仍能输出100%缺口 | 验证有限正价格及高低价关系；校验股票代码、名称、成交量；异常写入结果元数据 |
| 本地模型切分 | 大步长使 `split - forward_days` 为负，Python负切片反而纳入验证数据 | 隔离标签后必须仍有足够训练样本，否则拒绝运行 |
| 本地模型股票标识 | CSV 的股票代码与 `--code` 不同，结果仍以命令行代码标记 | CSV 含代码列时核对单一股票及代码一致性 |
| 本地模型输入 | 非有限OHLCV、不可能的高低价及缺失/时区日期进入模型 | 在特征计算前验证并拒绝 |
| 原实验预测器 | 对已标准化特征再次拟合标准化器，预测原始特征时量纲错误 | 保留原始均值/方差，并同步切片被选择的特征；测试实际预测输入与训练变换一致 |

## 核验方式

缓存键增加数据结构版本前缀，同时区分个股与指数，不复用旧版本可能错误的行情缓存；旧缓存文件不删除。

```bash
python -m compileall -q ema gap_screen local_model tail_screen tests
python -m unittest discover -s tests -v
python -m unittest local_model.test_offline -v
python gap_screen/screen_gapup.py --date 2026-09-28 --snapshot examples/gap_snapshot.csv --bars examples/gap_bars.csv --profile relaxed --out outputs/gap_demo.csv
```

测试使用合成数据与接口响应替身，包括真实取数器输出结构再传入下游的检查；没有执行交易或将合成结果当作历史收益。当前测试总数见 [验证记录](validation.md)。

## 尚未验证的部分

没有完成全市场联网运行、所有券商客户端适配、完整历史时点数据库或实盘收益验证。尾盘仍有分钟/板块请求数量上限和缺失数据评分兜底，不能宣称获得了全市场无遗漏排名。原实验模型内部调参和切分未完成全面时序审计，修复标准化错误不等于其全部验证结果已可靠。

目前未提供通达信条件选股公式；Python与券商公式的数值等价性也未验证。源码中的参数档位仍只是研究起点，不因代码测试通过而成为经过收益验证的策略。
