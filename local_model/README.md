# 本地技术指标预测与筛选实验

公开入口从原项目提取了技术指标计算，使用固定随机森林建立可运行的研究基线。它是简化入口，不等同于原项目全部自动搜索、校准、缠论增强或完整九条件筛选的迁移。

从仓库根目录运行：

```bash
python -m local_model.cli --code 000001 --days 1500 --forward-days 3 --profile standard
python -m local_model.cli --code 000001 --csv examples/daily.csv --end-date 2026-09-30 --profile strict
```

第二条中的 CSV 路径仅示意，需提供自己的文件。最少包含 `date,open,high,low,close,volume`，可选 `amount,pct_change`；中文日线列名也可识别。文件只应含所选一只股票。若含 `code/symbol/代码/股票代码` 列，会校验其全部为单个股票且等于 `--code`；不含代码列时需使用者自行保证归属。日期须为无时区且不缺失的交易日，OHLCV须为有限数值，且最高/最低价应覆盖开收盘价。输入至少需要清理后200条有效且已知标签的日线，推荐1500个自然日数据。在线取数调用 AkShare；接口与访问可用性另行决定，离线测试不证明在线接口可用。

## 使用者可修改的参数

| 参数 | 默认值 | 建议起始值与含义 |
|---|---|---|
| `--code` | 必填 | 所需6位股票代码，示例不构成推荐 |
| `--end-date` | 本机今天 | `YYYY-MM-DD`，使用已收盘交易日；休市日会显示实际最后一根K线日期 |
| `--days` | 1500 | 730/1500/2500自然日；更长样本不保证更准确，需考虑制度变化 |
| `--forward-days` | 1 | 1/3/5个交易日；不建议小样本直接预测很长周期 |
| `--return-threshold` | 0.005 | 0.005/0.01/0.02代表0.5%/1%/2%的标签涨幅门槛；实际标签门槛为 `min(max(所填值,交易日步长×0.001),0.15)` |
| `--profile` | standard | 三档模型概率筛选门槛，见下表 |
| `--min-probability` | 随profile | 0.50到1.00，可覆盖三档门槛 |
| `--output` | 不保存 | 可选JSON结果路径 |

| 推荐版本 | 参数 | 模型概率门槛 | 取舍 |
|---|---|---|---|
| 强限制 | `--profile strict` | ≥0.65 | 相同数据与模型下入选更少 |
| 标准 | `--profile standard` | ≥0.60 | 默认研究起点 |
| 弱限制 | `--profile relaxed` | ≥0.55 | 覆盖更广，需要更多人工复核 |

三档只改变入选概率门槛，预测步长、标签和模型不变时满足强⊆标准⊆弱。数值是便于试验的起点，没有通过跨时段验证选出；未经独立校准的模型概率不是实际成功概率，强限制也不保证低风险。`selected` 只表示达到了筛选门槛。

标签1表示未来收益达到门槛；标签0包括上涨但未达到门槛的情况，不能将它简单读作下跌。末尾未来收益未知的样本不参与训练。输出 `as_of` 是行情截止日，不是预测目标到期日。

## 原模型与九条件筛选源码

`experimental/predictor.py` 保留原项目的自动模型选择、集成与校准实验类；可通过 `from local_model.experimental.predictor import StockPredictor` 导入，搭配本模块指标与标签函数。随机森林以外的 XGBoost/LightGBM 是可选依赖。该源码不在默认 CLI 流程中，未完成全面时序审计，不宜直接引用其中准确率作为交易效果。

原实验模型的重复标准化问题已修复：保留训练时原始特征的均值/方差，并在特征选择后同步切片，预测与训练使用同一口径。此修复不等于完成原模型的整体验证；原模型内部切分和调参尚未统一加入预测步长隔离，其准确率仍不适合充当无泄漏验证结论。

`experimental/screen_stocks.py` 保留原九条件筛选源码，可从仓库根目录执行 `python -m local_model.experimental.screen_stocks --test 000001` 或 `--full`。它使用实时价格与手工配置报告期的财务数据，**不支持历史时点筛选**。参数在文件顶部直接修改，不接受上面预测 CLI 的 `--profile`。建议一次只改一类参数，记录日期与结果：

| 条件常量 | 原默认 | 强/标准/弱限制起始值 |
|---|---|---|
| `MAX_PRICE`，价格上限(元) | 10 | 8 / 10 / 20 |
| `MAX_MARKET_CAP`，流通市值上限(亿元) | 500 | 200 / 500 / 800 |
| `A_PB_MAX`、`A_PE_MAX` | 2、20 | (1.5,15) / (2,20) / (3,30) |
| `B_PB_MAX`、`B_PE_MAX` | 3、30 | (2,20) / (3,30) / (4,40) |
| `AMPLITUDE_LIMIT`，窗口最高价/最低价上限 | 4 | 3 / 4 / 5 |
| `NEAR_LOW_FACTOR`，价格/窗口低点上限 | 2 | 1.5 / 2 / 2.5 |
| `VOLUME_RATIO_THRESHOLD`，近20日均量/近60日均量下限 | 1 | 1.2 / 1 / 0.8 |
| `STAGNATION_MAX_CHANGE`，近20日绝对涨跌幅上限 | 0.20 | 0.10 / 0.20 / 0.30 |

`CONSOLIDATION_YEARS` 默认5年，建议保持5年比较三档；3/5/8年可做独立窗口实验，改变窗口会改变低点与振幅含义，不具包含关系。`BEST_MARKET_CAP=100` 仅给入选股票分档标记，不是额外过滤。`WEEKLY_MONTHLY_STRICT` 原默认False；True模式有“周月上涨”兜底，不能把它理解成纯粹更严格的集合，因此三档比较建议保持False。财务季报双增、年报缺失时保留等逻辑仍在原函数内，需要先理解再改。低价、小市值、低估值只是风格约束，不等于风险更低；财务PE口径也需核对。

## 验证与局限

日期相关设置还包括 `FINANCIAL_PERIODS`：依次填写 `(报告期末,年报期末)`，格式 `YYYYMMDD`。原研究默认从 `(20260630,20251231)` 开始尝试；不会自动发现最新报告期。可按数据源已有且已披露的季度更新（如3月31日、6月30日、9月30日、12月31日），不能仅因期末日期已到就假设报表已经公开。它会混用实时价格，修改报告期并不会得到当时的估值和股票池。营收/利润同比只是财务指标，不能直接等同于订单增长；行业代理标注也不能证明某公司为国企。

```bash
python -m unittest local_model.test_offline -v
```

默认模型按时间顺序80%/20%留出，在训练与验证间排除预测步长数量的样本，避免训练标签跨入验证期。展示验证准确率、平衡准确率及验证期多数类基准，然后使用全部已知标签样本重训，预测最新K线。未提供手续费、滑点、持仓约束或交易收益回测；验证期预测的标签可能互相重叠，不能视作独立试验。

公开入口不加载原缠论增强。原居中极值需要后续K线确认，原第三方集成会再次读取最新行情，未作为这里的历史预测特征。即使基础特征通过追加未来数据不变的测试，也不代表原始行情的复权、修订和数据获取没有偏差。在线前复权历史可能随未来公司行动调整；严格时点研究需保存当时可得快照。截止日为今天时日线也可能未收盘，应手动选择最近已收盘日。本文档的三档数值仅作为研究参数参考。
